## ۲. ایرادهای رفع‌شده در این بررسی

### ۲.۱ 🔴 پیش‌نمایش زنده صفحه را بدون CSS/JS نشان می‌داد (رفع شد)

**شدت:** بحرانی برای کار روزمره

Next.js 16 در حالت توسعه، درخواست‌های cross-origin به دارایی‌های `/_next/*` را
با **پاسخ ۴۰۳** رد می‌کند. چون این پروژه پشت پروکسی پیش‌نمایش (میزبانی مانند
`*.e2b.app`) اجرا می‌شود، این رفتار کل صفحه را می‌شکست. گزارش خود سرور:

```
⚠ Blocked cross-origin request to Next.js dev resource /_next/static/chunks/main-app.js
  from "3000-abc123.e2b.app".
```

سنجش پیش از رفع: از ۲۲ دارایی صفحه، **۸ مورد ۴۰۳ (یا ۳۰۸ ناشی از آن)** بود.
سنجش پس از رفع: **۲۲ از ۲۲ سالم**.

**رفع:** افزودن `allowedDevOrigins` به `next.config.ts`. این تنظیم فقط بر سرور
توسعه اثر دارد و بر خروجی تولید و build بی‌اثر است.

### ۲.۲ 🔴 خروجی GitHub Pages در چیدمان iframe مسدود می‌شد (رفع شد)

ترکیب `X-Frame-Options: SAMEORIGIN` و `frame-ancestors 'self'` اجازه نمی‌داد
صفحه داخل iframe دامنه‌ای دیگر (پروکسی پیش‌نمایش) بالا بیاید.

**رفع:** شرطی‌سازی بر پایه `NODE_ENV`. در توسعه `frame-ancestors *` و حذف
`X-Frame-Options`؛ در تولید **همان سخت‌گیری قبلی دست‌نخورده** می‌ماند
(با `next start` تأیید شد: `X-Frame-Options: SAMEORIGIN` و
`frame-ancestors 'self'`).

### ۲.۳ 🟠 پرش رنگ در حالت تاریک (رفع شد)

کلاس `dark` در `useEffect` اعمال می‌شد، یعنی **بعد از** نخستین رنگ‌آمیزی. هر
کاربری که حالت تاریک را انتخاب کرده بود، در هر بار بارگذاری یک «پرش سفید»
می‌دید. این با ادعای `docs/FEATURES.md` («بدون پرش رنگ») در تناقض بود.

**رفع:** اسکریپت مسدودکننده کوچک در `<head>` (`src/lib/theme.ts`) که پیش از
نخستین رنگ‌آمیزی اجرا می‌شود، `prefers-color-scheme` را هم در نظر می‌گیرد و
`colorScheme` را هم تنظیم می‌کند. `ThemeProvider` هم مقدار اولیه‌اش را از DOM
می‌خواند تا پس از hydration آیکون کلید تم هم‌گام بماند.

### ۲.۴ 🟠 میان‌برهای PWA روی GitHub Pages به ۴۰۴ می‌خوردند (رفع شد)

`scripts/fix-basepath.py` فقط `start_url`، `scope` و `icons` را اصلاح می‌کرد و
`shortcuts[].url` جا می‌ماند:

```json
"shortcuts": [{ "url": "/request" }, { "url": "/track" }, { "url": "/services" }]
```

روی Pages، `/request` زیر پیشوند `/Khadamat447/` نیست، پس کاربر به ریشه دامنه
(۴۰۴) می‌رفت.

**رفع:** افزودن حلقه `shortcuts` به `fix_manifest`.

### ۲.۵ 🟠 قواعد `Disallow` در `robots.txt` استاتیک بی‌اثر بود (رفع شد)

`src/app/robots.ts` مسیرها را بدون basePath می‌نوشت:

```
Disallow: /admin      ← روی Pages این مسیر وجود ندارد
```

صفحه‌های واقعی `/Khadamat447/admin` بودند؛ یعنی پیشخوان مدیریت، پیگیری و
جست‌وجو روی انتشار GitHub Pages **قابل ایندکس** می‌ماندند.

**رفع:** `robots.ts` از منبع یکتای `src/lib/basepath.ts` می‌خواند. حالا:
`Disallow: /Khadamat447/admin` و در استقرار دامنه‌ای همان حالت قبلی.

### ۲.۶ 🟡 پیش‌نمایش مدرک اشتباه نشان داده می‌شد (رفع شد)

در `wizard.tsx` فایل مبنا چنین پیدا می‌شد:

```ts
const file = incoming.filter((f) => f.name === attachment.name)[index] ?? incoming[0];
```

`index` اندیس در **فهرست پذیرفته‌شده‌ها** بود ولی روی **همه فایل‌های ورودی**
(شامل ردشده‌ها) اعمال می‌شد. با فایل‌های هم‌نام یا ترکیب پذیرفته/ردشده،
یا پیش‌نمایش **فایل اشتباه** نشان داده می‌شد یا `?? incoming[0]` یک فایل
بی‌ربط (حتی ردشده) را جلو می‌انداخت.

**رفع:** زوج `{ attachment, file }` نگه داشته می‌شود؛ هیچ جست‌وجو و اندکسی
لازم نیست.

### ۲.۷ 🟡 پیکربندی مرده و گمراه‌کننده (رفع شد)

`next.config.ts` داشت:

```ts
serverExternalPackages: isStaticExport ? [] : ["pg", "nodemailer"],
```

نه `pg` و نه `nodemailer` در `package.json` هستند و هیچ‌جای کد import نشده‌اند.
این خط سواستفاده‌کننده بود (این تصور را می‌داد سامانه پایگاه داده و ارسال
ایمیل دارد) و Next هم بی‌صدا نادیده‌اش می‌گرفت.

**رفع:** حذف شد. کامنت بالای فایل هم که از «API، پایگاه داده و پنل مدیریت»
حرف می‌زد، با واقعیت پروژه (تمام‌مرورگری) هم‌سان شد.

### ۲.۸ 🟡 ورودی‌های بی‌مصرف در `.gitignore` (رفع شد)

`.build-backup/` (اسکریپت دیگر آن را نمی‌سازد) و `tests/e2e/artifacts/`
(پوشه‌ای که وجود ندارد) حذف شدند.

### ۲.۹ 🟡 اجزای بی‌اثر lint (رفع شد)

۷ کامنت `eslint-disable-next-line` در کد هست اما پروژه **هیچ پیکربندی ESLint
ندارد** و اسکریپت `lint` هم تعریف نشده. کامنت‌ها فعلاً بی‌اثر هستند.

**رفع جزئی:** در این بررسی فقط گزارش شد؛ افزودن ESLint تصمیم مالک پروژه است.
اگر بخواهید، `next lint` با پیکربندی پیشنهادی Next اضافه می‌شود.

## ۴. پیشنهادهای بعدی (اولویت‌دار، بدون تغییر در این بررسی)

### الف) الزامات پیش از انتشار عمومی

1. **رمز عبور نمایشی در بسته سمت مرورگر است.** مقدار `447477` در
   `DEMO_CREDENTIALS` داخل JS کلاینت قرار می‌گیرد و احراز هویت فقط
   `localStorage` است؛ هر بازدیدکننده می‌تواند وضعیت را دست‌کاری کند. برای
   نسخه نمایشی کاملاً پذیرفته است، اما **نام دامنه باید صریحاً نگوید سامانه
   عملیاتی است**. پیشنهاد: یک نوار ثابت «نسخه نمایشی» در بالای `/admin`.
2. **`legal` / کد ملی در فرم‌ها.** اگرچه فعلاً هیچ داده‌ای به سرور نمی‌رود،
   پیش از اتصال به API واقعی، سیاست نگهداری و حذف داده لازم است.

### ب) بهبودهای ساختاری

3. **افزودن ESLint.** ۷ کامنت `eslint-disable` بی‌اثرند؛ فعال‌کردن
   `next lint` قواعد `react-hooks` و `@next/next` را زنده می‌کند.
4. **آزمون نوع‌ها در CI.** گردش‌کار حاضر فقط build می‌کند. افزودن
   `npm run typecheck && npm test` پیش از build، خطاها را زودتر می‌گیرد.
5. **لینک «پرش به محتوا».** برای کاربران کیبورد، افزودن
   `<a href="#main" class="sr-only focus:not-sr-only">` توصیه می‌شود.
6. **`trailingSlash` و `canonical`.** در حالت استاتیک `trailingSlash: true`
   است اما `alternates.canonical` و `sitemap.xml` بدون `/` پایانی تولید
   می‌شوند. GitHub Pages خودش ریدایرکت می‌کند، پس مشکل عملی نیست؛ برای
   یکدستی سئو، افزودن `/` پایانی به مسیرهای صفحه توصیه می‌شود.
7. **صفحه ۴۰۴ سفارشی.** در حال حاضر `_not-found` پیش‌فرض Next است و با
   زبان طراحی سایت هم‌خوان نیست.
8. **افزودن `verify` به قالب مجوز Markdown.** رندر `[x](javascript:...)`
   را مسدود نمی‌کند؛ چون محتوا فقط توسط مدیر نوشته می‌شود ریسک پایین است،
   اما یک `if (!/^https?:\/\/|^\//.test(href)) return;` کافی است.

### ج) اگر روزی سرور اضافه شد

`docs/FEATURES.md` بخش «د» را دارد. ترتیب منطقی: (۱) API و پایگاه داده،
(۲) احراز هویت واقعی کارکنان، (۳) ارسال واقعی پیامک/ایمیل، (۴) بارگذاری
فایل روی فضای ابری با اسکن ویروس. ساختار `src/lib/store/types.ts` از قبل
مطابق طرح پایگاه داده طراحی شده، پس این مسیر کوتاه است.
